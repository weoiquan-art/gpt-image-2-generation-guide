# JIN GPT Image 2 生图指南

一套面向角色资产、场景锚点、叙事关键帧、分镜、多图合成和精确编辑的 GPT Image 2 实战方法。

> 核心思路：把 Prompt 写成一份可审阅的视觉任务书。参考图负责身份与既有视觉事实，文字负责本次画面、构图、动作、光线，以及“哪些改变、哪些必须保持”。

本文最后核对日期：**2026-08-23**。模型能力与 API 参数以 [GPT Image 2 模型页](https://developers.openai.com/api/docs/models/gpt-image-2)、[OpenAI Image Generation Guide](https://developers.openai.com/api/docs/guides/image-generation) 和 [官方 Prompting Guide](https://developers.openai.com/cookbook/examples/multimodal/image-gen-models-prompting-guide) 为准。

## GPT Image 2 适合什么

GPT Image 2 的优势不只是“画得漂亮”，而是可以处理更像生产任务的请求：

- 根据结构化视觉说明生成图片；
- 使用一张或多张图进行编辑、合成与风格迁移；
- 在多轮工作流中保持人物、产品和布局；
- 生成包含明确文字、图表、界面或多面板的结构化视觉；
- 输出透明背景素材；
- 用同一张合格图继续做局部修改，而不是每轮从零抽卡。

官方当前把 `gpt-image-2` 作为新工作流的默认推荐，并支持 `low`、`medium`、`high` 三档质量。它的图像输入已经默认采用高保真处理，因此不要套用旧模型的 `input_fidelity` 调参习惯。

## 一分钟工作流

```text
定义图片用途
  → 选择资产类型
  → 为每张参考图分配唯一职责
  → 先定构图与唯一焦点
  → 再定空间、动作状态、光线和材质
  → 用九块结构写 Prompt
  → 生成基线图
  → 先验收目的与构图
  → 找出唯一主故障
  → 用“只改变 X，保持其余不变”做单变量编辑
  → 保存合格图、Prompt、参数和修改记录
```

### 开工前八问

- 这张图最终是角色锚点、场景锚点、产品图、叙事关键帧，还是分镜总览？
- 观众第一眼必须看到什么？
- 每张参考图固定什么？明确不继承什么？
- 多张人物图是否共同定义同一个角色？
- 本图只冻结哪一个动作或状态？
- 主光来自哪里？阴影落在哪里？
- 哪些内容绝对不能被编辑改变？
- 成功标准能否用肉眼判断？

## 九条核心规则

### 1. 先写用途，再写画面

把用途放在前面，例如“角色设定资产”“儿童绘本续页”“竖版广告”“AI 视频首帧”“技术信息图”。用途会帮助模型理解需要的布局、完成度和视觉语言。

### 2. 使用固定结构，不迷信神秘语法

官方建议采用稳定顺序：**背景 / 场景 → 主体 → 关键细节 → 约束**，并补充用途。短段落、标签、自然语言或 JSON 风格都能工作；生产环境优先选择人能快速扫描和修改的格式。

### 3. 每张图只承担一个主任务

- 角色锚点负责身份与服装，不承担剧情高潮。
- 场景锚点负责空间结构，不让临时人物抢焦。
- 叙事关键帧只冻结一个清楚动作瞬间。
- 九宫格只验证节奏与连续性，不直接当正式高清素材。

### 4. 参考图必须写职责

不要只说“参考这些图”。按编号写清每张图负责什么，以及它不应该迁移什么。多图合成时，还要写明图与图如何互动。

### 5. 把构图选择交代清楚

写景别、观察角度、主体占比、前中后景、负空间、裁切安全区和唯一焦点。不要期待参考图自动替导演完成构图。

### 6. 抽象词必须落到可见证据

“电影感、高级、紧张、真实”不能单独承担控制任务。继续写成光源、明暗面积、身体姿态、材质反光、空间层次和颜色关系。

### 7. 编辑时重复保持项

每一轮都重新声明哪些身份、几何、布局、品牌元素、相机角度、文字和背景必须保持。不要只写“继续改一下”。

### 8. 先做干净基线，再逐轮追加

长 Prompt 可以工作，但故障定位更困难。先做可用基线，再用“小而单一”的后续修改，例如“只把主光变暖”“移除右侧多余树木”“恢复原背景”。

### 9. 第 0 道验收永远是目的与构图

在修手指和清晰度前，把图缩成手机缩略图：唯一焦点、轮廓、层次和情绪是否仍然成立？如果不成立，先改构图。

## Prompt 九块结构

### 1. 用途 / Use Case

这张图要用于什么？需要什么完成度？

```text
用途：9:16 角色叙事关键帧，后续作为 AI 视频首帧。
```

### 2. 场景 / Scene

时间、地点、环境状态和空间尺度。

```text
清晨的王族学院入口大厅，石墙与深色木门形成宏大尺度，空间已经开始运转。
```

### 3. 主体 / Subject

主体身份和不可妥协特征。若参考图已明确，不要重复成一大段外观小说。

### 4. 参考职责 / References

逐张写“固定什么 / 不继承什么 / 如何组合”。

### 5. 构图 / Composition

画幅、景别、观察角度、主体占比、焦点、前中后景、负空间和裁切。

### 6. 动作与状态 / Action & State

只冻结一个动作瞬间，写明重心、手脚、视线与动作后的稳定状态。

### 7. 光影、材质与风格 / Lighting, Material & Style

写真实光源、位置、软硬、受光、阴影、弱补光，以及不同材质如何响应光。

### 8. 关键细节 / Important Details

文字、道具连接、品牌元素、面板顺序、必须出现的标志与易错细节。

### 9. 约束与输出 / Constraints & Output

写少量高风险排除项，以及尺寸、透明背景、文字准确度等输出要求。

## 多张参考图怎么分工

官方建议按编号描述输入图片，并说明它们如何互动。JIN 的做法再增加一层：每张图不仅写“要继承什么”，还写“不继承什么”。

| 参考图 | 负责固定 | 不继承 |
|---|---|---|
| Image 1：面部身份 | 脸型、五官、发型发色、瞳色、年龄感 | 白底、旧服装、原表情、原站姿 |
| Image 2：身体 / 服装 | 头身比例、整套衣服、鞋袜、配件位置 | 第二个角色、原背景、冲突的脸 |
| Image 3：场景 | 布局、尺度、材质、地标和主光方向 | 场景中的人物、临时道具、文字 |
| Image 4：风格 | 色彩、曝光、线条、纹理、空气和成像表现 | 角色身份、服装、姿势和场景结构 |
| Image 5：动作 | 单一姿态、重心、肢体角度和接触关系 | 原人物、服装、地点和调色 |

### 多图职责模板

```text
Image 1 只定义同一角色的脸、发型、发色、瞳色和年龄感；
不继承白底、原表情、原站姿和旧服装。

Image 2 只定义同一角色的身体比例、目标服装、鞋和配件；
Image 1 与 Image 2 共同定义唯一的同一角色，不得出现第二个实体。

Image 3 只定义场景布局、空间尺度、材质、地标与主光方向；
不继承图中的人物、文字和临时道具。

本次任务：让上述唯一角色自然站在 Image 3 的空间中，
身份与场景结构优先，不改变角色设计，也不重建场景。
```

## 角色与场景连续性

### 角色资产顺序

```text
面部与年龄感
  → 身体比例
  → 服装、鞋与配件
  → 正 / 侧 / 背多视图
  → 单角度叙事图
  → 表情与动作变化
```

- 面部锚点用中性光、少遮挡、清楚五官。
- 身体锚点完整露出头、手、鞋和服装下摆。
- 面部特写若参与服装连续性，也要穿目标服装。
- 同一轮不要同时换脸、衣服、年龄、姿势、画风和光线。

### 场景不是漂亮背景，而是坐标系

主场景图至少定义：中心轴、入口、出口、左右边界、地标、地面 / 墙面 / 顶面关系，以及主光源位置。

换机位时写六件事：

1. 摄影机位置；
2. 机位高度；
3. 朝向；
4. 瞄准点；
5. 景别与必须保留的边界；
6. 布局、时间、材质、地标和光源等不变项。

## 构图、光影与材质

### 构图七问

- 采用什么景别？
- 从哪里看？
- 主体占画面多少？
- 第一眼看什么，第二眼看什么？
- 前、中、后景分别做什么？
- 哪里必须留空？
- 轮廓、遮挡与裁切安全吗？

### 两个预检

- **Frame feasibility**：所有必须出现的信息能否在同一静态画面、同一景别中共存？
- **Constraint priority**：如果全身、表情、目标物和空间尺度冲突，本图优先保留什么？

### 光影六段因果链

| 层级 | 要回答什么 |
|---|---|
| 光源 | 光来自窗户、太阳、吊灯、火焰还是霓虹？ |
| 位置 | 相对主体的方向和高度？ |
| 性质 | 软硬、强弱、色温和扩散？ |
| 受光 | 照到哪些身体部位与材质？ |
| 阴影 | 暗面和投影落在哪里？ |
| 辅助 | 环境反射只保留哪些暗部细节？ |

### 材质写“如何接光”

- 金属：窄而清楚的高光、边缘磨损和细小划痕。
- 皮革：宽而低强度的高光、缝线、折痕和受力压痕。
- 布料：褶皱与柔和阴影服从重力，不出现塑料高光。
- 木 / 石：纹理尺度服从透视，接触处压暗并有局部磨损。
- 玻璃 / 湿地：反射只出现在真实光源与观察角度允许的位置。

## 多轮编辑：改变项与保持项

GPT Image 2 很适合基于合格图继续修改。关键不是把整份 Prompt 每次重写，而是明确**改变集合**与**不变集合**。

### 外科式编辑模板

```text
只改变：把主光从中性晨光改为柔和暖金色黄昏光。

必须保持：
- 同一角色的脸、发型、年龄、身体比例和服装；
- 原构图、摄影机位置、裁切、人物姿势与视线；
- 原场景布局、地标、道具位置和文字；
- 原图的饱和度范围与背景清晰度。

不得新增人物、文字、Logo、水印、道具或建筑结构。
```

### 为什么要重复不变项

“和上一张一样”可以利用上下文，但关键身份、几何、布局和文字一旦开始漂移，就应在每一轮重新写明。不要用含糊的“优化一下”“更高级”代替具体修改。

## 九宫格与多面板分镜

GPT Image 2 能处理多面板和结构化视觉，但九宫格仍应被当成**分镜验证器**，不是自动编剧器。

### 九宫格用于检查

- 节奏是否重复；
- 景别是否有变化；
- 人物方向、服装和比例是否连续；
- 场景地标与光线是否稳定；
- 每格是否有明确叙事工作。

### 提示至少写清

- `3 列 × 3 行`；
- 从左到右、从上到下阅读；
- 清楚的 1—9 编号；
- 每格一个具体视觉节拍；
- 每格的景别、唯一焦点和动作状态；
- 同一角色、服装、年龄、比例和视觉体系；
- 不出现额外格子、标题、对白、水印或无关文字。

通过的格子必须重新生成独立高清图。不要直接裁九宫格作为正式首帧：裁切会损失分辨率，相邻面板也可能干扰后续模型。

## 图中文字与透明背景

### 精确文字

官方建议把必须出现的文字放在引号中或使用全大写，并写清字体、大小、颜色、位置和出现次数。生僻品牌词可逐字母拼写。小字、密集信息图或多字体布局优先比较 `medium` 与 `high`。

```text
只出现以下文字一次，逐字准确，不增加任何字符：
"WELCOME BACK"

字体：粗体无衬线；
位置：画面上方居中；
颜色：暖白色；
要求：字距清楚，高对比，无水印、无其他文字、无额外 Logo。
```

### 透明背景

GPT Image 2 的透明背景目前属于预览能力。API 使用时：

```text
background="transparent"
output_format="png"  # 或 webp；JPEG 不支持透明
```

Prompt 仍要明确写：主体完全隔离、透明背景、不要场景、纯色底、棋盘格、额外投影或光晕。后续编辑时再次写“保持透明背景”，并在下游处理里保留 alpha 通道。

## 质量、尺寸与 API 选择

### 质量档位

| 任务 | 建议起点 |
|---|---|
| 大批量探索、预览、快速 A/B | `low` |
| 常规角色图、产品图、分镜、广告草案 | `medium` |
| 小字、密集图表、近距离人像、身份敏感编辑、最终成品 | 比较 `medium` 与 `high` |

### GPT Image 2 尺寸约束

- 最大边必须小于 `3840px`；
- 两条边都必须是 16 的倍数；
- 长短边比例不能超过 `3:1`；
- 总像素需在 `655,360` 到 `8,294,400` 之间；
- 超过 `2560 × 1440` 的结果更容易波动，应视为实验区。

常用稳定起点：`1024 × 1024`、`1024 × 1536`、`1536 × 1024`、`2560 × 1440`。

### Image API 还是 Responses API

- 单次从文字生成，或针对一组图片做一次明确编辑：优先 Image API。
- 需要对话式、多轮、可继续追问的图片工作流：优先 Responses API 的 image generation tool。

本仓库主要讲 Prompt 方法；具体请求格式请直接查阅 OpenAI 官方文档。

```

统一为 [目标视觉体系]。

Panel 1：[功能、景别、动作状态、唯一焦点]
Panel 2：……
Panel 3：……
Panel 4：……
Panel 5：……
Panel 6：……
Panel 7：……
Panel 8：……
Panel 9：……

要求：面板边界清楚；不增加或合并格子；
除 1—9 编号外不出现标题、对白、字幕、Logo 或水印。
```

### 风格反推模板

```text
分析风格参考图，但不要描述或继承其中的人物、服装、家具和具体地点。

提取能迁移到其他题材的视觉条件：
色彩体系、曝光结构、真实光源、方向与高度、光线传播、受光、阴影、
环境反射、空气状态、材质响应、空间层次和可确认的成像表现。

不要停在“电影感、胶片感、8K、高级感”等抽象词；
必须把它们翻译成肉眼可见的条件。
不要猜无法从画面确认的相机、镜头、胶片或后期软件。

先输出风格 DNA，再输出一段不复制原图内容的可迁移质量 Prompt。
```

## 生成后验收与单变量修复

### 固定验收顺序

0. 目的与构图；
1. 角色或产品身份；
2. 身体、手脚、关节、道具与接触；
3. 空间、透视、尺度、遮挡和接触阴影；
4. 人物、肢体、文字和物件数量；
5. 角色与环境的画风边界；
6. 文字、Logo、水印、乱码、背景重构与意外裁切。

### 故障定位表

| 唯一主故障 | 第一轮只改 |
|---|---|
| 像证件照、没有画面设计 | 机位、裁切、主体占比、前中后景、遮挡和最亮区 |
| 脸或年龄漂移 | 面部参考职责与保持项 |
| 服装 / 配件漂移 | 身体服装锚点与目标服装声明 |
| 出现第二个角色 | 多图共同定义唯一实体的说明 |
| 场景被重建 | 原布局、坐标、摄影机与不变项 |
| 角色像贴纸 | 主光、接触阴影、尺度、透视和遮挡 |
| 光影混乱 | 只保留一个主光，重写光源—受光—阴影 |
| 文字错误 | 精确引号、出现次数、字体位置；比较 medium / high |
| 编辑波及其他区域 | “只改变 X”并逐条重申保持项 |
